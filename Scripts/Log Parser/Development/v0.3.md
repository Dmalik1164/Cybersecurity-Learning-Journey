# Development Log - Version 0.3

## Objective

Extend the SSH log parser by extracting IPv4 addresses from security-relevant log entries and counting repeated occurrences. The aim of this version was to move beyond simply counting event types and begin identifying the IP addresses responsible for those events, providing more meaningful intelligence from the authentication log.

---

## Development Process

This version began with researching regular expressions and implementing a reusable function to extract IPv4 addresses from each log entry. Rather than embedding the regular expression inside every conditional, I created a dedicated `extract_ip()` function which returned a list of detected IP addresses for a given line. This made the code more modular and easier to maintain.

Once IP extraction was working, I introduced a second dictionary to track the occurrence count of each IP address. Unlike the event counter from v0.2, this dictionary used the extracted IP address as the key and incremented its value whenever the same address appeared again throughout the authentication log.

After validating the counting logic, I improved the console output by replacing the default Python dictionary output with a formatted SSH Event Summary and a dedicated IP Address report. During testing I noticed that most IP addresses only appeared once, creating unnecessary noise. To improve readability I added a simple filter so that only repeated IP addresses were displayed, making the output much more useful from a security monitoring perspective.

The final stage focused on improving maintainability by adding descriptive comments throughout the codebase and cleaning up the output formatting to resemble a small command-line security utility rather than debugging output.

---

## Challenges

The largest challenge in this version was understanding how dictionaries should be used to count occurrences. Initially I attempted to increment standalone variables rather than the values stored within the dictionary, and also mistakenly recreated the dictionary inside the processing loop, which reset the counts every iteration. Working through these problems reinforced how dictionaries store key-value pairs and why they must persist throughout the lifetime of the loop.

Another challenge involved program structure. My first attempt placed the IP counting logic before the IP extraction had taken place, meaning the variable did not yet exist. Reordering the logic to extract the IP address first before updating the dictionary resolved the issue and highlighted the importance of thinking through program execution step by step.

A final challenge was deciding where filtering should occur. Initially I considered only counting repeated IP addresses, but realised this would lose valuable information. Instead, I kept the counting logic independent and applied filtering only when displaying the results. This separated data collection from presentation and resulted in a cleaner overall design.

## Skills Developed

Through this version of the project I gained experience with:

Regular expressions (Regex) — extracting IPv4 addresses from authentication logs using Python's `re.findall()` function.

Function design — creating reusable functions to separate responsibilities and improve maintainability.

Dictionary-based data aggregation — storing IP addresses as dictionary keys and incrementing occurrence counts dynamically.

Nested conditional logic — combining event detection with IP extraction and occurrence counting.

Output formatting — replacing raw dictionary output with structured summaries suitable for command-line reporting.

Code readability — improving maintainability through descriptive comments, clearer variable names and cleaner program structure.

Security-focused reporting — recognising that repeated authentication attempts are generally more valuable than isolated events and presenting output accordingly.

---

## Outcome

Version 0.3 successfully extends the parser beyond event counting by extracting IPv4 addresses and tracking repeated occurrences throughout the authentication log. The parser now produces two clear reports: a summary of SSH authentication events and a filtered list of repeated IP addresses associated with those events.

This version demonstrates a progression from simple log parsing towards basic security analysis. Rather than only identifying what happened, the parser now begins identifying where repeated activity originated, providing a stronger foundation for future development.

The next planned version will build upon this work by associating specific IP addresses with individual authentication event types, allowing more detailed reporting and richer security analysis.
